# SURMEM 新站前后端契约（surmem-web ⇆ server）

> 更新：2026-10-16。新站为静态导出（`output: "export"`），接口经 Nginx 同源
> 反代（`/api/v1` → `localhost:8080`），无跨域。响应统一体
> `{code, msg, data}`，`code` 用标准 HTTP 语义（200/400/404/500）。

## 一、链路总览

| 链路 | 接口 | 前端入口 | 后台维护入口 | 状态 |
|---|---|---|---|---|
| 询盘提交 | `POST /api/v1/rfq` | `QuoteForm`（联系页） | ADP「rfq」域（列表 + status 推进） | ✅ 已通 |
| 滤芯系列内容 | `GET /api/v1/fc-series?locale=en-US` | `FilterSeriesGrid`（Products 页） | ADP「fc-series」域 | ✅ 已接 |
| 站点联系方式 | `GET /api/v1/site/bootstrap?locale=en-US` | `DynamicContact`（页脚 + 联系页） | ADP「站点外壳/页脚」 | ✅ 已接 |
| 其余公开接口 | `/home-*`、`/articles`、`/products/{id}` 等 | 新站暂无对应栏目 | — | ➖ 不接 |

## 二、取数策略：fetch-with-fallback

静态导出的页面在构建时把 `src/data/site.ts` 的默认文案渲染进 HTML
（保证首屏 SEO 与后端不可用时的兜底）；客户端水合后拉取后台数据，
**拉到非空才覆盖渲染**，失败静默回退（`content.ts` 返回 `null`）。

效果：

- ADP 后台改内容 → 前台**即时生效，无需重新构建**；
- 后端宕机 / 接口 404 → 页面完整可看，只是内容为内置默认；
- 绝不弹错误提示打断访客（询盘提交除外——那必须让用户知道结果）。

## 三、询盘契约（POST /api/v1/rfq）

请求体 18 字段（camelCase），前端 `QuoteForm.tsx` 的 `RfqPayload` 与后端
`RfqController` 接收字段一一对应，**禁止随意改字段名**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `requestType` | 是 | 只认 `quote` / `sample`，其余按 quote 落库 |
| `fullName` | 是 | 最长 128 |
| `workEmail` | 是 | 后端正则校验邮箱格式 |
| `company` `phone` `accountType` `monthlyVolume` `industry` `country` `partNumber` `quantity` `targetMicron` `requiredLeadTime` `application` `sourcePath` `sourceSeries` `sourceModel` | 否 | 各有长度上限，超长截断，空串落库为 NULL |
| `message` | 否 | 最长 20000；产品意向折进首行 |

落库表 `rfq_submission`；成功返回 `{code:200}`，校验失败 400，落库失败 500。
前端失败提示附「邮件兜底」话术，不丢客户线索。

## 四、滤芯系列契约（GET /api/v1/fc-series）

返回 `data: SeriesItem[]`，前端 `FilterSeries` 类型逐字段对齐：

```
{ id, slug, nameZh, nameEn, taglineZh, taglineEn,
  facetsZh: string[], facetsEn: string[], comingSoon }
```

- 新站固定 `locale=en-US`，渲染取 `nameEn / taglineEn / facetsEn`；
- `nameEn` 为空的条目前端不展示（兜底过滤）；
- `comingSoon: true` → 卡片挂「Coming Soon」角标，保留询盘入口；
- 特性点用原稿 `.tag` 小标签样式逐字还原。

## 五、联系方式契约（GET /api/v1/site/bootstrap）

取 `data.footer.contact`：

```
{ title, address, phone, qr, emails: string[] }
```

- `address / phone / emails` 全空 → 前端视为无数据，整块不渲染；
- 页脚（`DynamicContact`）与联系页左栏共用同一数据源；
- 电话渲染 `tel:` 链接、邮箱渲染 `mailto:` 链接。

## 六、后台操作路径（ADP）

| 想改什么 | 在哪改 | 前台生效方式 |
|---|---|---|
| 滤芯系列名称/简介/特性点 | ADP → fc-series 域（`fc_series` 表） | 刷新页面即生效 |
| 联系方式（地址/电话/邮箱） | ADP → 站点外壳 → 页脚 | 刷新页面即生效 |
| 查看客户询盘、推进处理状态 | ADP → rfq 域（`rfq_submission` 表，可改 `status`） | — |
